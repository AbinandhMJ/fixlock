# fixlock examples

Ready-to-copy configuration. Most of it is written for you by `npx fixlock init` and `npx fixlock setup <assistant>`; use these when you want to see or adapt the files by hand.

## AI assistants

| Assistant | File here | Goes to | Generated by |
|---|---|---|---|
| Claude Code | [`assistants/claude-code/.mcp.json`](assistants/claude-code/.mcp.json) | `.mcp.json` | `fixlock setup claude-code` |
| Claude Code (hook + permissions) | [`assistants/claude-code/settings.json`](assistants/claude-code/settings.json) | `.claude/settings.json` | `fixlock setup claude-code` |
| Cursor | [`assistants/cursor/mcp.json`](assistants/cursor/mcp.json) | `.cursor/mcp.json` | `fixlock setup cursor` |
| GitHub Copilot (VS Code) | [`assistants/copilot/mcp.json`](assistants/copilot/mcp.json) | `.vscode/mcp.json` | `fixlock setup copilot` |
| OpenAI Codex | [`assistants/codex/config.toml`](assistants/codex/config.toml) | `~/.codex/config.toml` | `fixlock setup codex` |
| Gemini CLI | [`assistants/gemini/settings.json`](assistants/gemini/settings.json) | `.gemini/settings.json` | `fixlock setup gemini` |
| Any MCP client | [`assistants/any-mcp-client/mcp.json`](assistants/any-mcp-client/mcp.json) | wherever your client reads MCP servers | |

These use `npx --no-install fixlock`, which needs fixlock installed in the project (`npm i -D @abinandhmj/fixlock`). Otherwise use `"args": ["-y", "@abinandhmj/fixlock", "mcp"]`.

The rules files (`AGENTS.md`, `.cursor/rules/fixlock.mdc`, `.github/copilot-instructions.md`, …) list your project's own locks, so they're generated rather than copied: `npx fixlock sync`.

## Git hooks

`npx fixlock install-hook` writes plain git hooks. If your project uses a hook manager, add fixlock there instead:

| | |
|---|---|
| [`hooks/husky/`](hooks/husky/) | Husky v9: `pre-commit` and `post-commit` |
| [`hooks/lefthook.yml`](hooks/lefthook.yml) | Lefthook |

## See it working

```bash
npx @abinandhmj/fixlock demo --keep   # builds a demo repo with all of this set up, and keeps it
```
